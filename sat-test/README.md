# Тестовое задание SAT — сайт + Google Sheets

Сайт проводит 30-минутный тест из 8 заданий (4 Math + 4 R&W), проверяет ответы на сервере
(Google Apps Script) и пишет результат в Google-таблицу. Ключи никогда не попадают в браузер.

```
Браузер (web/)  ──POST text/plain JSON──►  Apps Script Web App (apps-script/)  ──►  Google Sheets
  только условия заданий                    ключи, проверка, время старта           Результаты, Ответы, …
                                            └─► уведомления HR: email, Telegram
```

| Папка | Что внутри |
| --- | --- |
| `web/` | Статический сайт: `index.html`, `styles.css`, `app.js`, `config.js`, `logo.svg` (~60 КБ, без сборки и зависимостей) |
| `apps-script/` | Сервер: код для проекта Apps Script, привязанного к таблице |
| `dev/` | Локальный сервер и эмулятор Apps Script для разработки и тестов (не деплоится) |
| `tests/` | Unit- и интеграционные тесты сервера, сквозные тесты в браузере |
| `docs/HR_GUIDE.md` | Инструкция для HR и проверяющего |

## Развёртывание

Всё делается из **Google-аккаунта JTS**, а не личного аккаунта разработчика: иначе скрипт
перестанет работать, когда у разработчика заберут доступ.

### 1. Таблица и скрипт

1. Создайте пустую Google-таблицу, например «SAT — тестовое задание».
2. **Расширения → Apps Script**. Удалите содержимое `Code.gs`.
3. Для каждого файла из `apps-script/*.gs` создайте файл с тем же именем (**＋ → Скрипт**) и вставьте содержимое:
   `Config`, `Validation`, `Grading`, `Store`, `Api`, `Notify`, `Setup`.
4. **Настройки проекта (⚙) → Показывать файл манифеста appsscript.json** → вставьте `apps-script/appsscript.json`.
5. В редакторе выберите функцию `setup` → **Выполнить** → подтвердите доступы.
   Создадутся все листы, формулы, цвета, защита, вопросы по умолчанию и триггер «раз в 10 минут».
6. Обновите вкладку таблицы — появится меню **SAT-тест**.

Вместо ручного копирования можно использовать [clasp](https://github.com/google/clasp):
`clasp create --type sheets --rootDir apps-script` → `clasp push`.

### 2. Web App

1. **Начать развёртывание → Новое развёртывание → Веб-приложение**.
2. «Выполнять от имени»: **Я (аккаунт JTS)**. «У кого есть доступ»: **Все**.
3. Скопируйте URL вида `https://script.google.com/macros/s/…/exec`.

### 3. Сайт

1. В `web/config.js` впишите URL: `apiUrl: 'https://script.google.com/macros/s/…/exec'`.
2. Замените `web/logo.svg` логотипом JTS, а цвета — переменными в начале `web/styles.css` (`--brand` и др.).
3. Опубликуйте папку `web/` на любом статическом хостинге:
   - **Cloudflare Pages / Netlify / Vercel**: новый проект из этого репозитория, каталог публикации `sat-test/web`, без команды сборки.
   - **GitHub Pages**: опубликовать содержимое `sat-test/web`.
4. Подключите поддомен, например `test.<домен JTS>`.

### 4. Настройки и секреты

- Лист **«Настройки»**: email для уведомлений, контакт HR, текст «Спасибо», срок ответа N,
  ссылка на текст согласия, пороги, длительность.
- Telegram (необязательно): создайте бота через @BotFather, добавьте его в чат HR,
  в «Настройках» укажите ID чата, а токен — в **Apps Script → Настройки проекта → Свойства скрипта**:
  `TELEGRAM_BOT_TOKEN = 123456:ABC…`. Токен не хранится ни в коде, ни в таблице.
- Доступ к таблице — только сотрудникам JTS по имени. «Все, у кого есть ссылка» — запрещено.
- Меню **SAT-тест → Отправить тестовое уведомление** проверяет email и Telegram.

### 5. Перед запуском

1. Пройдите тест сами (сценарии — в п. 12 ТЗ), проверьте строки и уведомления.
2. Удалите тестовые строки из «Результатов», «Ответов» и скрытого листа «Попытки».
3. В редакторе скрипта выполните `resetAttemptCounter` — нумерация начнётся с SAT-0001.

## Обновление

- **Вопросы, ключи, пороги, тексты** — в листах «Вопросы» и «Настройки», без правки кода.
  Правки применяются к новым попыткам сразу (кэш сбрасывается при редактировании, в худшем случае — через 5 минут).
  После правки вопросов: меню **SAT-тест → Проверить лист «Вопросы»**.
- **Код сервера**: вставьте новые файлы → **Развёртывания → Управление → ✎ → Версия: новая → Развернуть**.
  URL при этом не меняется. После изменения структуры листов запустите `setup` (данные не стираются).
- **Сайт**: обновите файлы на хостинге.

## API

Один адрес Web App, `POST`, тело — JSON, заголовок `Content-Type: text/plain` (без CORS-preflight).

| action | Что делает | Ответ |
| --- | --- | --- |
| `config` | читает «Настройки» | `open`, длительность, число заданий, тексты, контакт HR, списки для анкеты |
| `check` | проверяет анкету, ищет попытки по телефону и email | `status: new` / `in_progress` (+ данные для продолжения) / `expired`; ошибки `ALREADY_COMPLETED`, `CONTACT_MISMATCH` |
| `start` | повторно проверяет дубли, создаёт попытку, фиксирует старт | `attemptId`, `token`, задания без ключей, `deadline`, `serverNow` |
| `resume` | продолжение на том же устройстве по токену | как `start` или `status: done` |
| `save` | черновик и флаги в «Попытки» (раз в 30 с и при возврате на вкладку) | `savedAt`, `deadline`, `serverNow` |
| `submit` | проверка, запись в «Результаты» и «Ответы», уведомление HR; идемпотентно | `ok` — без баллов |

Коды ошибок: `VALIDATION` (с `errors` по полям), `TEST_CLOSED`, `ALREADY_COMPLETED`, `CONTACT_MISMATCH`,
`BAD_TOKEN`, `ATTEMPT_CLOSED`, `SERVER_ERROR`.

Надёжность: время старта и дедлайн хранит сервер, браузер считает остаток по `performance.now()`
от последней синхронизации; ответы сохраняются в `localStorage` при каждом изменении; при ошибке
сети повтор через 2, 4, 8, 16 с, затем каждые 30 с; все записи в таблицу — под `LockService`;
триггер раз в 10 минут закрывает брошенные попытки по черновику («Не завершён»).

Безопасность: строки кандидата пишутся в таблицу с апострофом (формулы не выполняются, «5,0» не
становится числом); задания уходят в браузер только после старта и без ключей; `save`/`submit`
принимаются только с токеном попытки; невидимое поле-ловушка отсекает ботов без записи в таблицу.

## Разработка и тесты

Нужен Node.js 18+. Зависимостей для запуска сайта и тестов сервера нет.

```bash
cd sat-test
npm run dev        # http://localhost:8080 — сайт + настоящий код apps-script/ в эмуляторе
npm test           # unit- и интеграционные тесты сервера (сценарии п. 12 ТЗ)
npm install && npm run e2e   # сквозные сценарии в Chromium (Playwright), скриншоты — tests/e2e/screenshots/
```

Локальный сервер хранит таблицу в памяти. Отладочные адреса: `GET /dev/sheets` (все листы),
`GET /dev/mail` (уведомления), `POST /dev/clock?minutes=31` (сдвиг часов сервера),
`POST /dev/trigger` (закрыть просроченные попытки). Переменные: `PORT`, `DURATION_MIN`, `HR_CONTACT`, `API_DELAY_MS`.

Эмулятор не вычисляет формулы Google Sheets и не проверяет форматирование — формулы «Итог теста»,
«Резерв» и подсветку нужно проверить в настоящей таблице (сценарии 8, 18, 24 п. 12 ТЗ).
